# Shelter Cove — project brief for Claude Code

This repo is currently a minimal "Coming Soon" placeholder for the Shelter
Cove beach house site. It is deliberately not the full reservation app.

## History

Through 2026-08-24 this repo held a full, database-backed Next.js
reservation app (login, calendar, booking, admin, photo gallery, etc.) on
Cloudflare Workers, with D1 (SQLite) and R2 (photo storage) behind it. That
app — and its D1 database and R2 bucket — were intentionally torn down and
replaced with this static Coming Soon page. The full app's source is
recoverable from git history (look at commits before the removal) if it's
ever brought back; the Cloudflare D1 database and R2 bucket themselves were
permanently deleted, so any reservations/user/photo data is gone for good.

## Stack (current)

- **Next.js 16** (App Router, TypeScript) with **@opennextjs/cloudflare**
  deploying it to Cloudflare Workers
- No database, no storage bucket, no auth — just a static page.

## Deployment

Cloudflare Workers Build is connected to the `jaheaton-zeus/Beach-House-App`
GitHub repo. Every push to `main` triggers a build (`npm run deploy`, which
runs `opennextjs-cloudflare build && opennextjs-cloudflare deploy`) and
redeploy automatically. No manual deploy steps needed once this repo is
pushed to.

Live at `sheltercove.aheaton.com`.

## Commands

```bash
npm install
npm run dev              # regular Next.js dev server
npm run preview           # builds + runs in the actual Workers runtime (more accurate)
npm run deploy             # builds + deploys to Cloudflare (also happens automatically on git push)
npm run lint
npx tsc --noEmit
```

## Gotchas still worth knowing

- **Fonts load via a `<link>` tag in `layout.tsx`**, not `next/font/google`.
  The build environment's font fetch during `next build` returned 403s in
  testing — likely CI IP rate-limiting on Google's side, a known flaky
  pattern. Runtime `<link>` loading avoids the build-time dependency
  entirely. This still applies even though the app itself is now minimal.
- **`npx tsc --noEmit` locally is not a reliable predictor of the Cloudflare
  build's type-check step**, because `cloudflare-env.d.ts` (Cloudflare's
  Workers runtime types) only exists after running `wrangler types`/`npm
  run build` — it's git-ignored and isn't generated by a plain `next dev`.
  Before pushing anything that touches `fetch()` or other ambient globals,
  run `npm run build` locally rather than trusting bare `tsc`.
